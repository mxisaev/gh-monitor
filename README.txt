DeployTray — Windows 10/11

1. Установи официальный GitHub CLI, если ещё нет:
   winget install --id GitHub.cli --exact
2. Открой НОВЫЙ терминал и авторизуйся:
   gh auth login
   Проверка: gh auth status
3. Распакуй архив в постоянную папку, например C:\Tools\DeployTray.
4. Дважды нажми Start.vbs (запуск без консольного окна).
5. В настройках впиши реальные репозитории owner/repo, каждый с новой строки.
   Workflow name contains: пустое поле — все активные workflow (по умолчанию).
   Если вписать deploy, будут показаны только workflow с deploy в имени.
   Нажми Save.

Работа
• Значок содержит первые три буквы/цифры заголовка конкретного run (display_title):
  Malina production → MAL, PKee release → PKE.
  Если заголовок пустой, используется имя workflow.
  Для информативного заголовка задай run-name в GitHub Actions YAML, например:
  run-name: Malina — production
  Фильтр deploy по-прежнему применяется к имени workflow, не заголовку run.
• Один значок на каждый активный запуск. Серые буквы — ожидание, жёлтые — выполнение.
  Фон прозрачный; цвет меняется вместе со статусом. Наведение: статус, заголовок, repo, ветка.
• Двойной клик открывает запуск на GitHub.
• Проверка каждые 15 секунд ПОСЛЕ завершения предыдущей проверки.
• queued / in_progress / waiting / pending / requested показываются как активные.
• Завершённый workflow исчезает, независимо от успеха или ошибки.
• Постоянный серый GH: приложение работает. Наведение показывает состояние.
• При отсутствии запусков остаётся только GH. Это не статус последнего деплоя.
• После успешного workflow GH зелёный 5 минут с момента завершения.
  Каждый новый успех продлевает срок; ошибка связи имеет приоритет (красный GH).
• При ошибке проверки GH становится красным; старые значки помечены UNKNOWN.
• Правый клик по любому значку: Settings, Exit.
• Windows может прятать новые значки в меню «^». Перетащи значок в видимую область.
• Отслеживается весь workflow деплоя, включая build/test, а не конкретный deploy job.

Автозапуск (необязательно)
Win+R → shell:startup → помести туда ЯРЛЫК на Start.vbs.

Настройки
Правый клик по постоянному GH → Settings.
Если GH не видно, проверь меню «^» возле часов.
Если приложение не запускается, открой PowerShell в папке и выполни:
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File .\Start.ps1
Повторный запуск при уже работающем экземпляре ничего не делает.

Безопасность / состав
Приложение не запрашивает и не записывает токен. Выполняет только gh api GET
на github.com для чтения workflow runs. Токен используется самим gh.
Это не изоляция credentials: программа, работающая от твоего пользователя,
в принципе может пользоваться его авторизацией gh. Здесь таких иных команд нет.
config.json хранит только repo, фильтр и интервал. Нет автообновлений и телеметрии.
Start.ps1 компилирует открытый DeployTray.cs встроенным .NET Framework.
Не требуется Python, Electron или дополнительный .NET SDK.
Start.vbs запускает Windows PowerShell со скрытым окном; ExecutionPolicy Bypass
действует только для этого процесса, системная настройка не меняется.
Если политика организации запрещает скрипты, потребуется разрешённая сборка EXE.

Проверка версии
Код просмотрен в Linux; компиляция и поведение Windows tray на реальной Windows
в этой среде не проверены. Это первая версия для проверки на твоём компьютере.
